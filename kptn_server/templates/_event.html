Both paths therefore produce byte-identical markup: what the stream appends is exactly what a page reload would have rendered. The folds -- one per pipeline or stage, one per task -- are here for the same reason. The stream sends a fold as ``fold_shell``, open and empty, and appends rows into its body; the page renders the same markup around the rows it already holds. Where every row goes is decided in ``kptn_server.console_layout``, never here and never in app.js. Every value here goes through Jinja's autoescaping. ``event.text`` is pipeline output -- untrusted bytes read out of the run's log file -- and this is the only place it is turned into markup.
